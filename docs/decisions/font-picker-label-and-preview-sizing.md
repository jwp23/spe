# Font Picker Label and Preview Sizing

Decision: The font picker's anchor labels the current family in the UI font, while the drop-down list previews each family in its own typeface. Both widths are measured from the families on offer rather than fixed, and each list row is set at a point size that normalizes the face's x-height onto 0.53 em (enlarging only, capped at 2x the base size).

Rationale: the two halves of the picker do different jobs. The list is a specimen sheet — a row set in the family it offers is the whole point. The anchor is a label read at a glance, and rendering it in the family's own face cost more than it gave: "Helvetica Bold Oblique" overflowed the fixed 150px anchor and painted its second line outside the button, and a cursive selection left the toolbar showing a wisp. Labelling in one known face also bounds the anchor's width — a family can only widen it by having a longer name, never by being a wide face — which is what makes measuring the width safe. A fixed width cannot stay correct once rows carry per-face sizes, and clamping a measured width would put us back to hiding part of a name.

The previews normalize on x-height because that, not point size, is what makes two faces look the same size. The bundled cursives declare x-heights of 0.33–0.46 em against the 0.52–0.54 em measured from the faces the Standard 14 resolve to, so a single point size across the list is what left them illegibly small. The ratio is read from each embedded face's own font program via skrifa, so a family added later is sized correctly without anyone tuning a constant. The Standard 14 render through whatever face the system supplies — the face we could measure is not the face that reaches the screen — so they report no ratio and stay at the base size, which is the baseline everything else normalizes toward. Scaling only ever enlarges: a face at or above the target already reads well, and shrinking it would undo that.

Deliberately not done: the rest of the toolbar's sizing was left alone, so the font control's metrics may not match the size stepper and page field.
