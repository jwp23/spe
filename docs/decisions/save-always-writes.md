# Save Always Writes a File

Decision: `write_overlays` (`src/pdf/writer.rs`) writes a plain copy of the source PDF through the same `lopdf` load-and-save round-trip used for baking overlays, even when the overlay list is empty, rather than returning `Ok` without touching the destination.

Rationale: with an empty overlay list, `write_overlays` previously returned `Ok(SaveReport::default())` having written nothing at all — GUI Save and Save As, and the IPC `save` command, all reported "Saved to `<path>`" while producing no file (spe-47n). "Saved" must mean a file exists at the destination; a success response that leaves the destination untouched is not honest, and is exactly the class of bug PR #127's IPC honesty work exists to close off elsewhere in the app. Routing the empty case through `Document::load` + `doc.save(destination)` — the same path the non-empty case eventually reaches after baking overlays — keeps one code path and one `WriterError` surface for both cases, and keeps the upstream inode-based overwrite-source guard (which gates every save, not just non-empty ones) in effect uniformly.

Rejected alternative: `fs::copy(source, destination)`. This would take a second, divergent path through the filesystem that never touches `lopdf` at all — normalization the load/save round-trip applies (e.g. how `lopdf` re-serializes the document) would differ between an empty-overlay save and a save with at least one overlay, and any future check added to the load/save path (validation, additional normalization) would have to be duplicated in the copy path or silently not apply to empty-overlay saves. Reusing the same round-trip both fixes the honesty bug and removes the divergent path.
